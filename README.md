# crx-toolbox

一个用于浏览器控制台调试、京东订单评价与知乎页面伪装的 Chrome 扩展（Manifest V3）。

## 功能

### 1. 控制台日志控制器

通过扩展弹窗上的三个开关，按需屏蔽当前页面输出的 `console.log` / `console.info` / `console.warn`。

- 开关状态保存在 `chrome.storage.local`，**跨页面、跨会话持久生效**，新打开的标签页会自动应用。
- 采用注入脚本改写页面主世界的 `window.console`，因此对页面自身脚本的日志同样有效，而非仅屏蔽扩展自身的输出。
- 每个开关旁实时显示当前状态（`log: 已禁用` / `log: 已启用`）。

### 2. 京东商品一键评价

在京东订单评价相关页面，点击弹窗中的「京东商品一键评价」按钮后自动完成评价流程：

- 逐条点击五星好评
- 向评价文本框填入评语（多条商品时**各不重复**）
- 点击提交

支持三种页面场景，进入页面后也会自动触发：

| 页面 URL 特征              | 行为                             |
| -------------------------- | -------------------------------- |
| `myJdcomments/myJdcomment` | 找到「评价」入口并跳转后执行评价 |
| `orderVoucher`             | 直接执行评价                     |
| `saveCommentSuccess`       | 点击「查看更多」                 |

> 该功能依赖京东页面当前的 DOM 结构，页面改版后可能失效。

#### 评语从哪来

评语有两条来源，**AI 是加分项，不是必需品**：

1. **AI 实时生成**（默认开启，需先配置端点）——一次调用按输入框数量生成一组互不相同的评语。
2. **本地词池**（保底）——6 条人工撰写的完整评语，取用时先洗牌再按序取，保证同页多个输入框两两不同。

以下任何一种情况都会**静默降级**到本地词池：开关关闭、未配置端点或密钥、请求失败、限流、超过 8 秒未返回、返回内容为空或被截断。降级时不弹窗、不重试、不打断流程——一键评价在任何情况下都走得通。

> 注意：**接入本功能后，即使 AI 全程关闭，评语也不再是旧版本那条固定文案**，而是从词池中取。

### 3. AI 评语设置

AI 的开关与端点配置都在**扩展设置页**（弹窗里刻意不放 AI 界面：弹窗是高频操作面，配置是一次性动作）。两种进入方式：

- `chrome://extensions` → 本扩展详情页 → **扩展程序选项**
- 右键点击工具栏上的扩展图标 → **选项**

设置页最上面是一行总开关「启用 AI 评语」，**拨动立即生效**，不需要再点保存。下面的端点配置与验证结果只在开关开启时展示；**关闭开关只是收起并停用，已保存的配置与上一次的验证结果都不会被清除**，重新开启即可继续用。

| 配置项     | 说明                                                                    |
| ---------- | ----------------------------------------------------------------------- |
| `base_url` | OpenAI 兼容端点，如 `https://api.deepseek.com`。末尾的 `/v1` 可写可不写 |
| `api_key`  | 端点密钥，默认掩码显示，可点「显示」查看明文                            |
| `model`    | 模型标识，如 `deepseek-flash`；验证成功后下拉框会列出端点支持的模型     |

填好后点**保存**（这三项不做改完即存），点**验证**可做连通性自检：先 `GET /models` 查密钥与模型列表，再发一次极小生成请求确认真正要走的路径通不通。两步结果分别展示，第二步失败不会覆盖第一步的结论；失败时会给出实际请求的完整 URL、HTTP 状态与端点返回的原始错误，便于区分「密钥错 / 路径错 / 网络不通」。

base_url 用 `http://` 时会提示密钥将以明文传输。

**关于安全**：密钥以明文保存在浏览器本地存储（`chrome.storage.local`），只有扩展自己的设置页与后台脚本能读到，**网页中运行的脚本取不到、也不会写进 console**；验证结果里若端点回显了密钥，会被替换成掩码。仍建议使用权限受限的密钥。

### 4. 知乎伪装

popup 的「知乎伪装」分组有两个独立开关，默认都关闭。

**文档视图**（仅 `*.zhihu.com` 生效）

- 把知乎页面换皮成 POPO 风格浅色技术文档：隐藏顶栏/Logo/搜索、左右侧栏、右侧推荐模块、关注按钮、头像/徽章、作者悬浮名片、整条作者操作栏（赞同/反对/评论/收藏/喜欢/分享/更多/收起）、提问/写想法编辑器、右下角浮动 AI/回到顶部按钮、收录于合集入口、「N 人赞同了该回答」等社区元信息、热评卡与评论区、信息流封面、视频封面与视频播放器、刷新时的白色骨架屏/loading，以及版权页脚。
- 保留问题标题、正文、作者名与话题标签；作者名弱化为署名文本且不再触发悬浮名片，热评卡与评论区整体隐藏。
- **保留正文里的「阅读全文 / 收起正文」按钮**，长回答仍可展开；作者操作栏本身仍然隐藏。
- 页签标题替换为与正文解耦的技术文档标题（按 URL 稳定映射），favicon 替换为中性文档图标；知乎 SPA 路由重写标题后仍会重新接管。
- 顶部加伪文档页眉（面包屑参考内部文档「Agent 行为指标监控体系」）、正文上方加同文档的总体架构图、页尾加伪文档页脚。
- 左侧加 POPO 团队空间风格侧边栏：云空间/团队空间面包屑、出海项目组、搜索、首页、目录树（文件夹/文档，当前文档高亮）、底部迁入/上传/回收站；正文整体右移让出空间，窄屏下自动隐藏侧边栏并恢复居中。
- 长回答/长文章会在正文前半段随机插入一份相同的架构图，整页最多一份；短正文与折叠正文不插入，点「阅读全文」展开或关闭时相应增删。
- 信息流/列表里的每张正文卡片内部底部会显示一份紧凑架构图；只改变卡片高度，不新增或重排列表项，避免影响瀑布流。长正文展开后改为正文内嵌图，同一张卡片不重复；滚动加载的新卡片会在停止滚动后补插。
- 标题不再显示序号或章节前缀，问题标题使用正文色，字号与正文一致（约 15px），仅靠字重区分层级。
- 信息流卡片之间不再有分隔线或边框，但保留原有上下间距与内边距；信息流外层容器（`Topstory-mainColumnCard` / `Topstory-content`）的阴影与边框也去掉；架构图的虚线分隔去掉，自身留白保留。
- 关闭后无需刷新，标题、图标、配色与全部隐藏元素立即恢复。

**精简图片**（仅知乎生效）

- 按图片在页面上的**渲染尺寸**判定：宽度 ≥ 400px 或高度 ≥ 300px 即折叠，不占版面；外层封面/插图容器与正文顶层媒体块会一并折叠，避免留下空白。
- 覆盖初始加载、无限滚动/动态插入、懒加载、`src` / `srcset` 替换与窗口缩放；关闭后立即恢复。
- 只处理 `<img>`；CSS 背景图、iframe 内图片与 `<video>` 封面不受影响。

**已知限制**

- 地址栏、链接悬停状态栏、右键菜单与 DevTools 网络面板里的 `zhihu.com` 无法伪装；正文文字本身仍可能暴露来源。
- 知乎改版后个别品牌元素可能漏隐藏，此时页面仍可正常阅读；选择器集中在 `zhihu-camouflage.css` / `zhihu-camouflage.js` 中维护。
- 扩展重载前已打开的标签页需要刷新后才会应用新脚本。

## 安装

无需构建，直接以「已解压的扩展程序」加载：

```bash
git clone <repo-url> crx-toolbox
```

1. 打开 `chrome://extensions`
2. 右上角开启**开发者模式**
3. 点击**加载已解压的扩展程序**，选择仓库根目录
4. 扩展即安装完成（图标出现在工具栏）

修改代码后，回到 `chrome://extensions` 点击扩展卡片上的**重新加载**按钮即可。

## 使用

**控制台开关**：点击工具栏图标 → 切换 `console.log` / `console.info` / `console.warn` 对应的开关。切换会立即作用于当前标签页，并持久化到之后打开的所有页面。

**京东评价**：打开京东订单评价页 → 点击工具栏图标 → 点击「京东商品一键评价」。是否用 AI 生成评语由**设置页**最上面的「启用 AI 评语」开关控制（默认开启，需先配好端点）。

弹窗里「京东商品一键评价」按钮的文字前有一个小圆圈，圈里是 `AI`，**不出现文字**，含义只看边框颜色：

| 圆圈    | 含义                                                               |
| ------- | ------------------------------------------------------------------ |
| 不出现  | 没配过（三项一项都没填），或在设置页关掉了 AI                      |
| 🟡 黄框 | 配了，但最近一次验证没通过（没验过、验失败，或改了配置后结论作废） |
| 🟢 绿框 | 三项配好，且最近一次验证通过                                       |

它只是状态显示，**不能点**——要改就去设置页。绿色只说明「上次验证通过」，不保证每次调用都成；端点临时抽风仍会静默降级到本地词池。

**AI 设置**：`chrome://extensions` → 本扩展详情页 → 「扩展程序选项」（或右键工具栏图标 → 「选项」），详见上文「AI 评语设置」。

**知乎伪装**：点击工具栏图标 → 「知乎伪装」组 → 切换「文档视图」或「精简图片」。两个开关都立即生效并持久化；两者都只对知乎页面生效，其他网站的图片与样式不受影响。

## 项目结构

```
.
├── manifest.json      扩展清单（MV3）
├── background.js      Service Worker：初始化开关状态、页面加载后重注入、AI 评语的全部网络调用
├── content.js         Content Script：消息处理、页面主世界脚本注入、京东自动化、本地评语池
├── zhihu-camouflage.js / .css  知乎文档视图的 content script 与样式
├── image-hiding.js / .css      知乎大图隐藏的 content script 与样式
├── injected.js        注入到页面主世界的脚本，负责真正改写 window.console
├── popup.html         弹窗界面（内含样式）
├── popup.js           弹窗逻辑：读取/写入开关、发送消息
├── options.html       设置页界面（内含样式）
├── options.js         设置页逻辑：AI 总开关、配置读写、密钥掩码、验证结果渲染
├── src/assets/        图标资源（`doc-icon.svg` 为文档视图的 favicon）
├── openspec/          规格驱动变更工作流（proposal / spec / design / tasks）
└── .claude ｜ .agents AI 编码代理的技能与命令配置
```

### 工作原理

扩展需要屏蔽的是**页面脚本**的日志，而 Content Script 运行在隔离的 JavaScript 世界中，改写其中的 `console` 无法影响页面。因此扩展通过两条通道协作：

```
popup.js ──chrome.storage.local──▶ 持久化开关状态
    │
    └──tabs.sendMessage──▶ content.js（隔离世界）
                              │
                              ├─ 注入 injected.js 到页面主世界
                              └─ CustomEvent(TOGGLE_CONSOLE_METHOD)
                                       ▶ injected.js 改写真正的 window.console
```

`background.js` 会在每个页面加载完成后重新下发一次已禁用状态，保证新页面同样生效。

AI 评语的请求路径则是另一条：`content.js` 只发一条消息，真正的网络调用全部由 `background.js` 发出。

```
content.js ──runtime.sendMessage({action:'generateReviews'})──▶ background.js
   │                                                              │
   │                                              chrome.storage.local 读配置与密钥
   │                                                              │
   │◀──── { ok: true, reviews: [...] } 或 { ok: false } ── POST {base_url}/chat/completions
   │
   └─ 拿不到结果就用内联在 content.js 里的本地词池
```

放在 Service Worker 里有两条硬理由：`content.js` 的 `fetch` 按页面 origin 走 CORS，第三方端点不会为 `jd.com` 发 CORS 头；而 Service Worker 有 `host_permissions`，不受 CORS 约束。另外密钥也就此不必进入运行在 `<all_urls>` 上的页面脚本。

文档视图与精简图片走第三条路径：popup 只写 `chrome.storage.local`，两个内容脚本监听 `chrome.storage.onChanged` 自行应用，不需要 `tabs.sendMessage`，因此切换会同时作用于所有已打开的同类标签页。样式由 manifest 在 `document_start` 注入，内容脚本只负责给 `<html>` 加/删门控属性。

## 开发

```bash
yarn install        # 安装依赖（仅 Prettier）
npx prettier --write .   # 格式化代码
```

代码风格由 `.prettierrc` 定义：单引号、`printWidth: 170`、`tabWidth: 2`、`arrowParens: 'avoid'`。

项目当前没有测试、lint、CI 与构建步骤。验证方式为在浏览器中重新加载扩展后手工验证，详见 [AGENTS.md](./AGENTS.md)。

## 变更流程

仓库使用 [OpenSpec](https://github.com/Fission-AI/OpenSpec) 进行规格驱动的变更管理：

- `openspec/specs/` —— 已确认的能力规格
- `openspec/changes/` —— 进行中的变更（proposal → design → tasks → 实施）
- `openspec/changes/archive/` —— 已归档的变更
